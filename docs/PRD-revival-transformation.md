# PRD: Revival 照片美化应用跨平台「真软件化」改造

---

## 1. 项目信息

| 字段 | 内容 |
|------|------|
| **项目名称** | revival_true_software_transformation |
| **编程语言栈** | Vite + React 18 + TypeScript + MUI + Tailwind CSS |
| **桌面框架** | Electron 31 + electron-builder 24 |
| **移动端框架** | Capacitor 6 (Android) |
| **原始需求** | 将 Revival 从「网页套壳 Electron 应用」改造为具备**桌面原生能力 + Android 兼容 + 响应式 UI**的真正跨平台照片美化软件 |

---

## 2. 产品定义

### 2.1 产品目标

> **一句话定义**：将 Revival 从 React SPA 网页套壳升级为具备系统托盘、原生菜单、自动更新、文件关联、原生图片处理、任务栏进度等桌面原生特征，同时通过 Capacitor 兼容 Android 移动端的跨平台「真软件」照片美化工具。

### 2.2 用户故事

| # | 用户故事 |
|---|---------|
| US-01 | **作为一名摄影爱好者**，我希望软件能像真正的桌面应用一样拥有系统托盘和原生菜单，以便我随时快速打开/切换，而不会被浏览器标签页打扰。 |
| US-02 | **作为一名批量处理用户**，我希望在批量导出时看到任务栏进度条，且能使用原生对话框选择文件/保存路径，以便获得流畅的桌面操作体验。 |
| US-03 | **作为一名移动端用户**，我希望在 Android 手机上能触控操作照片美化，界面自动适配手机屏幕，以便随时随地进行简单的照片处理。 |
| US-04 | **作为一名桌面端用户**，我希望双击图片文件能直接用 Revival 打开，以便减少「打开软件 → 拖入图片」的操作步骤。 |
| US-05 | **作为一名长期用户**，我希望软件能自动检查更新并一键安装，以便始终使用最新功能和获得更好的兼容性。 |

## 3. 技术规范

### 3.1 需求池

#### P0（必须有 — 核心改造基线）

| ID | 需求 | 验收标准 |
|----|------|---------|
| R-01 | **系统托盘**：Electron 进程常驻系统托盘，支持显示主窗口/退出 | 托盘图标显示正确，右键菜单可用 |
| R-02 | **原生应用菜单**：文件/编辑/视图/模板/窗口/帮助菜单完整 | 快捷键生效，菜单导航到对应页面 |
| R-03 | **原生文件对话框**：打开/保存使用系统原生对话框 | 支持多选图片，支持图片格式过滤 |
| R-04 | **文件关联**：安装包注册 .jpg/.png/.heic/.webp 文件关联 | 双击图片后 Revival 打开并显示该图片 |
| R-05 | **安装包构建**：electron-builder 生成 Windows NSIS 安装包 | 安装后可启动，桌面快捷方式创建成功 |
| R-06 | **Android 兼容**：Capacitor 6 构建 Android APK | APK 可安装运行，基本美化功能可用 |
| R-07 | **响应式布局**：三断点（<640px / 640-1023px / ≥1024px）自适应 | 三种屏幕尺寸下布局合理、功能可用 |
| R-08 | **平台检测**：运行时自动识别 Electron/Android/Web 环境 | 各平台 API 调用正确，无跨平台异常 |

#### P1（应该有 — 体验增强）

| ID | 需求 | 验收标准 |
|----|------|---------|
| R-09 | **自动更新**：electron-updater 检测/下载/安装更新 | 启动时检查更新，有新版本提示用户 |
| R-10 | **Sharp 原生图片处理**：缩放/转换/压缩/缩略图/元数据读取 | 比 Web Canvas 处理速度快 3 倍以上 |
| R-11 | **任务栏进度**：批量导出时显示 Windows 任务栏进度条 | 导出过程进度实时更新，完成后清除 |
| R-12 | **手机端底部抽屉**：触控拖拽式参数调节面板 | 类似 iOS 照片编辑体验，拖拽流畅 |
| R-13 | **PWA 支持**：manifest.json + Service Worker 离线缓存 | 可添加到 Android 桌面，离线可打开 |
| R-14 | **EXIF 提取**：通过 exifr 读取相机参数（型号/光圈/快门/ISO） | 4 种模板正确显示相机参数水印 |

#### P2（可以有 — 锦上添花）

| ID | 需求 | 优先级说明 |
|----|------|-----------|
| R-15 | **macOS/Linux 安装包**：dmg + AppImage 构建 | 跨平台发布需求，可后续迭代 |
| R-16 | **iOS 兼容**：Capacitor iOS 平台支持 | 需 macOS + Xcode 环境 |
| R-17 | **触控手势**：双指缩放/旋转/拖动 | 移动端更自然的操作体验 |
| R-18 | **深色/浅色主题切换** | 目前仅深色模式，主题切换可扩展 |
| R-19 | **国际化 (i18n)** | 当前仅中文，后续可支持多语言 |

## 4. 待确认问题

| # | 问题 | 建议决策方向 |
|---|------|-------------|
| Q-01 | **自动更新的发布服务器 URL**：当前配置为 `https://releases.example.com`，需要确认正式发布 URL | 可使用 GitHub Releases 或自建更新服务器 |
| Q-02 | **Android 构建签名**：APK 发布需要签名密钥，是否需要配置 CI/CD 自动签名？ | 建议使用 Android Studio 生成签名密钥库 |
| Q-03 | **Sharp 的二进制包体积**：Sharp 依赖原生二进制文件，会增加 Electron 打包体积，是否接受？ | Sharp 约 20-30MB，建议保留以换取原生处理性能 |
| Q-04 | **macOS/Linux 优先级**：当前构建配置已支持 macOS (dmg) 和 Linux (AppImage)，是否在本阶段同步发布？ | 建议 P0 先做 Windows + Android，P2 再扩展 |
| Q-05 | **文件关联后首次启动处理逻辑**：双击图片打开后，应用应直接进入编辑器并加载该图片，需明确交互流程 | 建议通过 `process.argv` 接收文件路径，通过 IPC 传给渲染进程 |
| Q-06 | **移动端模板适配**：哈苏风/小米风/卡片参数等模板在手机端是否需要简化 UI？ | 建议保持功能一致，但控制面板参数数量可折叠/分组 |
| Q-07 | **数据存储方案**：是否需要将用户偏好设置持久化？Electron 用 `electron-store`，Android 用 Capacitor Preferences | 已引入 `@capacitor/preferences`，可统一抽象存储层 |
